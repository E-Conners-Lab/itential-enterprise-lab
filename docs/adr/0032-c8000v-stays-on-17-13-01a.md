# 0032 — C8000v stays on the loaded IOS XE 17.13.01a; supersedes ADR 0012

- **Status:** accepted (supersedes 0012)
- **Date:** 2026-09-06

## Context

ADR 0012 chose 17.18.4 because 17.13 is a Standard-support release whose
software maintenance ended 2024-11-30. The owner already holds
`c8000v-17.13.01a` on EVE-NG, wants to start the topology without a fresh
CCO download, and the lab's purpose is automation demos, not running a
supported release. RESTCONF, NETCONF and gNMI are all present in 17.13.

## Decision

Phase 4 builds the five C8000v nodes from the existing
`/opt/unetlab/addons/qemu/c8000v-17.13.01a/` image. The manifest row for
`c8000v` records 17.13.01a as the running version with 17.18.4 as the
documented upgrade target; the verify test S3.6 compares `show version`
against the manifest's *running* version.

## Consequences

- No download or EVE-NG image import for the routers in Phase 4.
- The lab runs an unmaintained IOS XE train; that is acceptable because the
  routers face no untrusted network. Moving to 17.18.x later is a manifest
  row change, an image import and a new ADR.
- Anything in the automation that turns out to need a newer YANG model is
  flagged in that phase rather than assumed.
